# v0.2.0 release plan

Status: in development, based on `main` at `99dfff5`. No release date or tag is
scheduled. This plan covers the 13 open issues reviewed on October 21, 2026.

The release should improve generated workflows' handling of real commands,
filesystem effects, and completion evidence. Compiler behavior must remain
independent of a skill's name, wording, domain, and provider. A passing stub
run establishes mechanics only; it does not establish answer quality.

## Scope and sequence

Every issue below remains open until its requested behavior is implemented and
verified. The rollout tracker [#17](https://github.com/trailofbits/calcifier/issues/17)
coordinates owner feedback; it is not an additional compiler feature.

The first increment implements #8 and #19. The next increment provides configured
worker capabilities and call requirements for #7, including repair after a full
dry-run mismatch. For #11, neutral regressions cover explicit build effects,
caller-provided isolation, hard dry-run suppression and the permitted manual route.
The command contract states that declaring mutation does not isolate a process.
These fixtures do not establish the
quality of new real-provider generations or create a process sandbox.

The next increment addresses #9 through file gathering in `prepare_context`,
validating all selected source and manifest paths against resolved authorized
roots before any reads. For #10, `ensure_directory` can preflight the full
subprocess output set and excluded roots before creating the directory. Neutral
compiler/runtime regressions cover internal and escaping symlinks, complete
LF/CRLF content, pinned resources, intermediate collisions, project-contained
outputs, explicit replacement policy, and clean subprocess writes. These helpers
do not constrain arbitrary trusted Python or external processes; generated
recipes must use them with the workflow's complete input and output sets.

For #16, the compiler can return an advisory suitability note without rejecting
or classifying source skills. The final accepted candidate's note reaches the
prepared artifact, CLI, and compiler trace; code validation and the whole dry
run still apply. Neutral guidance and procedure fixtures cover intact source
instructions, repair without stale assessments, and CLI delivery. Whether a
real compiler identifies advisory skills usefully still needs owner review.

For #12 and #14, neutral runtime regressions preserve source-required fields
through grouped rendering and verify saved reports at a trusted destination
against an independently known complete inventory. They cover required conditions
and caller fields across categories,
empty fields, escaped table content, absent/empty/directory/partial/duplicate
reports, and a complete saved report. The delivery fixture's whole compiler
dry run remains **unverified** at its stub-dependent inventory check; subsequent
delivery branches are exercised at runtime with stub workers. These tests
establish the available mechanics and authoring pattern, not that a real
compiler consistently generates it. Owner generation acceptance remains open.

The #12 follow-up also requires final findings and coverage after validation
and retries, with phase history kept separately. A neutral regression excludes
a refuted candidate, retains a confirmed finding, and preserves explicit
unprocessed-file coverage when a retry stays blocked. A successful retry clears
that coverage gap. The whole compiler dry run remains **unverified** where
schema-synthesized phase coverage cannot match the independent input inventory;
runtime tests exercise both final artifacts using scripted workers.

For #15, neutral old/new replace-by-default importers reproduce
the loss behind successful per-input counters. Aggregating inputs preserves
both records without relying on newer append APIs; an intentionally partial
saved artifact still fails the independent final check. Compiler suppression
leaves predeclared external files absent and reports their verification frontier
as unverified, including downstream content coverage. Runtime validation and
existing unplanned-path checks remain intact. Generation acceptance is still
an owner task.

Additional dry-run regressions keep caught artifact gaps unverified while
allowing the remaining code to execute, preserve later deterministic failures,
and exercise helper-returned paths under absolute output-root redirection.
Required Path inputs use a separate temporary tree; relative output roots named
`input`, `input/reports`, and `.` no longer collide with a synthesized project.

For #13 and #18, neutral compiler/runtime regressions use independently
observed checks and complete input coverage. They exhaust a multi-page
inventory beyond the page boundary, reject a
capped inventory, and distinguish empty inputs from blocked, uninspected, and
zero-execution measurements. A separate stub worker claims completion while an
independent host checker reports unresolved obligations or lint failures with
an exit-zero transport status; the recipe preserves those observations and
rejects completion. Its whole compiler dry run remains **unverified** at the
stub worker's reasoning-completion gate, after running the independent checker.
The pagination fixture's whole dry run passes with real neutral commands.

Scoped issues have API support or neutral authored workflow regressions. General
API contracts remain in the compiler prompt; domain-specific workflow advice
has been removed. The tests establish supported mechanics, not
that a real compiler extracts every required check, performs useful reasoning,
or consistently generates these patterns. All issues remain open pending
review and owner generation acceptance; the rollout tracker remains active.

## Verification and release gates

- Run focused offline regressions for each increment, then `gmake verify`.
  Tests use stub providers and never invoke live Claude or Codex. Do not run
  mutation testing locally.
- Always attempt the complete compiler dry run with synthesized inputs and
  stub agents. Preserve time/call limits and distinguish `passed`, `failed`,
  and `unverified` coverage.
- Keep generated evidence outside Git. Preserve the owner's checkout and use
  ordinary pushes from the isolated `release/v0.2.0` worktree.
- Owners run representative live acceptance after fixes in an appropriate
  isolated environment. Do not inspect held-out fixtures, cohort lists, or
  results. Offline checks cannot substitute for owner acceptance.
- Before release, reconcile this scope with unresolved issues, finish the
  changelog with the actual release date, check every version surface, build
  and verify the distribution artifacts, and follow the existing signed-tag
  publishing workflow. Creating this branch does not publish a release.
