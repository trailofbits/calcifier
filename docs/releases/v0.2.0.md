# v0.2.0 release notes

Release date: **2026-10-23**.

This release adds compiler and runtime support for optional commands, configured
worker capabilities, resolved file gathering, complete output preflight,
suitability notes, and standalone recipe environments. Implementation and review
fixes landed in [PR #20](https://github.com/trailofbits/calcifier/pull/20).

## Shipped changes

- Optional-command fallbacks can distinguish launch failures and local timeouts
  through `RecipeError.command_failure`. Shared-budget exhaustion remains fatal;
  validation and output-limit failures remain errors (#8).
- Generation, repair, and whole compiler dry runs receive the configured role's
  actual capabilities. Calls can require operations before invoking a worker.
  Requirements do not grant tools or filesystem access (#7).
- `prepare_context(files=..., readable_roots=...)` validates the entire resolved
  selection before reading source files or manifests. Internal symlinks,
  explicitly authorized external inputs, and pinned resources remain supported.
  Bounded text chunks preserve UTF-8 and LF/CRLF contents in pageable bundles.
  Use ordinary Python reads for files Python parses (#9).
- `ensure_directory(output_files=..., exclude_roots=...)` preflights all declared
  intermediate and final destinations before directory creation or subprocess
  writes. Collision, symlink, and excluded-root checks preserve existing output
  protection. Trusted recipes must declare their complete output set; this is
  not process isolation (#10).
- Compiler suitability notes reach the accepted artifact, CLI, traces, and final
  graph warnings. Control characters are rejected, failed compilation clears
  stale notes, and baseline fallback discards rejected candidate warnings (#16).
- Generated recipes and retained baselines include PEP 723 metadata with a
  Python minimum of at least 3.13 and the exact generating Calcifier version.
  Headers preserve shebangs, first- or second-line encoding declarations,
  literals, and LF/CRLF bytes (#19). See [direct execution](../usage.md#execution)
  for script-runner usage and resource requirements.

Review fixes also cover unpacked path arguments, suppressed worker writes,
wrapped and direct missing-artifact errors, missing default inputs, tuple path
collections, and independent temporary trees for synthesized inputs and outputs.
Existing host-output collisions still fail compiler preflight before scratch
redirection; this behavior was explicitly retained after review.

## Validation and remaining work

`gmake verify` checks the lockfile, Ruff, ty, portable plugin recipes, and the
offline test suite. Required CI for PR #20 passed, including Windows, Python
3.13 and 3.14, coverage, dependency audit, and distribution builds. Release
metadata and distribution artifacts are also checked by
`scripts/verify_artifacts.py`.

Whole compiler dry runs are attempted with synthesized inputs and stub agents.
Suppressed writes and checks that depend on stub reasoning remain explicitly
**unverified**. They are not promoted to passed results. No live provider CLI or
held-out acceptance material was used for this release work.

Neutral authored workflows exercise explicit build effects, required-field
rendering, reconciled final findings, complete inventory accounting, independent
verification, saved delivery, and accumulated imports (#11–#15, #18). These tests
establish supported mechanics. They do not establish that a real compiler
extracts every required check, consistently generates those workflows, or
produces useful reasoning.

[Issue #19](https://github.com/trailofbits/calcifier/issues/19) is complete. The
remaining issues #7–#18 stay open for follow-up, coordinated by the
[#17 rollout tracker](https://github.com/trailofbits/calcifier/issues/17).
Unperformed owner generation and end-to-end acceptance are documented validation
limits rather than prerequisites for publishing v0.2.0. Any later live acceptance
remains owner-run; it does not replace the offline regressions.

## Release metadata and publication

The package, runtime `__version__`, plugin manifest, and project lock entry use
`0.2.0`; the changelog uses `2026-10-23`. A source-only release check verifies
these surfaces against `v0.2.0` before tagging.

The release uses an annotated, signed `v0.2.0` tag whose commit is reachable from
`main`. The existing publication workflow verifies the tag signature and
reachability, reruns verification, audits dependencies, builds and checks the
wheel and source archive, and publishes to PyPI with attestations when the
GitHub release is published.

Changed recipe bytes require fresh trust. Direct script runners retain direct
Python execution's trust behavior. Review source and dependencies before
execution; the new helpers do not isolate trusted Python or subprocesses.
